SIFT1M: MAIN FINDINGS AND RECOMMENDED ALGORITHM

For the SIFT1M dataset, the main challenge is to retrieve similar vectors from a database of one million vectors while maintaining high recall and low search latency. In this benchmark, HNSW is the best method when search speed is the main priority, as it achieves the lowest measured latency at the 90%, 95% and 99% recall targets. At the 95% target, HNSW achieves approximately 96.38% recall with a latency of 0.1116 ms per query, making it about 4.96 times faster than Exact Flat. However, this speed comes at the cost of memory and index construction time, since HNSW stores both the raw vectors and a graph connecting them. The selected configuration uses approximately 656.3 MB of memory and takes 55.12 seconds to build.

Under a tighter memory or index construction budget, IVF-PQ is a suitable alternative for this dataset. At the 95% recall target, it achieves approximately 96.46% recall with a latency of 0.1732 ms per query, using 538.3 MB of memory and taking 14.88 seconds to build. Compared with the selected HNSW configuration, IVF-PQ requires approximately 118 MB less memory and builds about 3.71 times faster, while its query latency is about 1.55 times higher. Hence, IVF-PQ offers a useful balance between search speed, memory consumption and construction time, without sacrificing recall at these particular measured operating points.

IVF-RaBitQ is another alternative when balancing search performance and construction cost. At the 95% recall target, it achieves approximately 96.06% recall with a latency of 0.1850 ms per query, using 546.2 MB of memory and taking 13.02 seconds to build. It builds faster than the selected IVF-PQ configuration, although its search is slightly slower and its memory consumption is slightly higher. At the 99% recall target, IVF-RaBitQ searches faster than IVF-PQ, with latencies of 0.4065 ms and 0.4583 ms per query respectively, but requires more memory. Therefore, the choice between the two IVF methods depends on the required recall level and the relative importance of latency, memory and build time.

If exact retrieval is required, Exact Flat is the most suitable method. It achieves 100% recall with a latency of 0.5536 ms per query, uses approximately 512.0 MB of memory and takes about 0.107 seconds to build. In this experiment, the compressed methods also retain the raw vectors for exact reranking, so they do not reduce total estimated memory below Flat. LSH is less suitable for high-recall SIFT1M search because it is slower than Flat at all three compared recall targets. At the 95% target, LSH takes 1.6740 ms per query, despite its short build time.

Overall, HNSW is recommended for SIFT1M when fast search is the main requirement and sufficient memory and construction time are available. Under a tighter resource budget, IVF-PQ is the preferred balanced alternative around the 95% recall target, while IVF-RaBitQ is worth considering at higher recall targets. Exact Flat remains suitable when exactness or frequent rebuilding is more important than query speed.

These findings apply to the recorded SIFT1M benchmark on an Apple M4 using Faiss 1.15.1. Latency is single-threaded batch time divided by the number of queries, while memory is an estimated index size including retained reranking vectors, rather than measured process RAM. Each recall target selects the fastest measured configuration meeting that target, so the selected configurations may achieve different actual recall levels.
